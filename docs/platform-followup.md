# 根据三平台现状报告完成的优化

本轮以 [三平台现状报告](platform-status-report.md) 的差距为依据。软件版本保持 0.8.0，
推荐仍使用 v4；改动已通过独立验收，并于 2026-11-25 整合到主目录。

## 1. 已解决的问题

| 报告中的差距 | 本轮实现 | 可以检查的结果 |
| --- | --- | --- |
| 规则账号忽略活动概率、默认点赞 | 按 Persona 的发帖、点赞、评论概率决策；每 tick 的创作计划只抽样一次，设置发帖间隔；先阅读再互动 | 0 概率账号在三平台/三个 seed 下不产生对应发帖、点赞、评论；正发帖概率的新账号也可以创作 |
| 平台风格主要停留在样本文字 | 分别实现小红书、X、Reddit 的行为选择与回应；语气、示例、媒体类型和可见正文参与选择 | 小红书保存实用笔记和查看图集；X 围绕原帖回复、转发/书签；Reddit 按相关社区和规则发帖 |
| 无标签内容主要依赖新鲜/热门 | 增加有界文字兴趣召回和排序，从 Persona 与真实反馈提取词语 | 旧的无标签咖啡内容能被召回；中英文均有固定条件检查；诊断不进入账号观察 |
| 同城只做子串匹配、样本地点单一 | 按明确地点层级匹配，并支持世界配置中的别名；新建样本覆盖多个城市/区县 | “杭州”匹配“杭州市/西湖区”，但不匹配“杭州路”；“York”不直接匹配“New York”；多个层级须同时符合 |
| X 关系只有静态二跳与点赞计数 | 社交点赞按实际时间衰减，学习近期作者互动，召回对读者的回复及熟悉作者 | 相同条件下近期点赞信号强于旧信号；较早的相关回复可通过对话通道进入候选 |
| Reddit 选择第一个加入的社区、背景账号加入所有社区 | 从可见主题/描述与账号兴趣选择社区，排除无发布权限和无相关性的目标；先查看规则，再固定发帖社区 | 不把咖啡帖发到无关摄影社区；未批准的受限社区不作为发布目标；每个新增背景账号初始只加入 1–2 个公开社区 |

自然语言社区规则仍是参与语境，不是通用自动判罚；文字兴趣是词语近似，不是训练的
语义模型。这些结果不能等同于真实用户生态、模型运营能力或厂商推荐一致率。

## 2. 规则账号的具体行为

活动字段使用 `posting_probability`、`like_probability`、`comment_probability`，也兼容
Persona 导入中的 `activity`、`social_behavior` 字段。发帖概率按可创作的虚拟 tick 抽样，
不是每次动作都重新尝试，默认发布后至少间隔 3 tick。示例文本在单次运行中不反复
作为新的发布重复使用，后续采用有限的提问模板；模板不代表原创推理能力。

小红书可按账号地点探索附近、保存兴趣相关笔记、继续看图集；X 可在 For You 与
Following 间浏览，转发保留原帖身份，回应当前正文；Reddit 可以发现/加入相关社区，
发帖前查看规则与实际发布权限，按社区语境提问。明确不感兴趣的主题用负反馈处理，
不把反对个人兴趣自动变成 Reddit 的质量 downvote。

新增背景角色区分浏览者、贡献者、提问者和观察者，活动概率不同。角色是开发配置，
没有真实人群比例或真人行为校准。新默认样本仍只有 4 账号、6 主帖和 3 图片；视频
能力通过真实临时视频文件验证，不增加默认视频或媒体体量。已有源世界不会重灌数据。

## 3. 推荐配置与读取边界

- `text_weight=0.45`：文字兴趣分量，可设为 0 关闭；v1/v2/v3 不使用该分量。
- `relationship_half_life_ticks=48.0`：X 的关系证据衰减半衰期。
- 文字反馈最近最多 96 条，每条最多 24 个词语；候选正文最多读取 1024 字符，文字
  召回最多使用 8 个正向词语。没有引入分词模型、嵌入服务或模型权重。
- 近期作者偏好最多读取 256 条反馈；显式关注关系和历史只读回放继续保留。
- 地点别名从世界的 `world.json` 读取，最多 64 个地点，每个最多 16 个别名，冲突会
  被拒绝。它不是地理距离或自动地名识别服务。

地点配置示例（添加到相应世界的 `world.json`）：

```json
{
  "location_aliases": {
    "杭州": ["杭州市", "Hangzhou"]
  }
}
```

可选行为设置保存在 Persona 的 `culture`，例如：

```json
{
  "posting_probability": 0.08,
  "like_probability": 0.2,
  "comment_probability": 0.15,
  "content_formats": {"text": 0.3, "image": 0.5, "gallery": 0.2},
  "culture": {
    "location": "杭州市",
    "posting_cooldown_ticks": 3,
    "save_probability": 0.25,
    "follow_probability": 0.08,
    "gallery_probability": 0.5
  }
}
```

X 还可设置 `repost_probability`；Reddit 可设置 `join_probability`。概率均为 0–1，
不是页面新增控件；可通过 Persona 数据使用。字段兼容说明见 [数据准备](data.md)。

## 4. 验证记录

新增行为回归位于 [平台人设检查](../tests/test_platform_personas.py)，覆盖零概率、
首次创作、阅读顺序、地点/别名、无标签兴趣、近期关系、社区选择与固定、权限、
媒体、语气、背景角色和输入校验。原有“克隆与相同 seed 轨迹”检查现在明确设置
创作者概率为 1、读者概率为 0；不再依赖旧的概率忽略行为来保证两次发布。

三平台分别用 seed 1、7、42 做 16-agent / 8-tick / 6-step 的隔离试跑，每场 768 动作：

| 小红书 | 1 | 4 | 15 | 0 | 413 | 0 | 0 |
| 小红书 | 7 | 5 | 16 | 0 | 346 | 0 | 0 |
| 小红书 | 42 | 2 | 15 | 0 | 301 | 0 | 0 |

| X | 42 | 5 | 0 | 21 | 511 | 0 | 0 |

共 9 场、6912 次动作，全部 completed；导出包含新的推荐配置，源世界计数保持不变。
这些是开发策略下的流程与跨 seed 验证，没有把发布/互动数量当作模型能力分数。
相较此前试跑，账号数量、轮数和策略配置都有变化，不适合直接计算优劣百分比。

最后审查补充了“草稿保持已读规则的目标社区”的约束；对应回归与完整检查结果见
[验证状态](validation.md)。

九场验收进程的累计峰值 RSS 为 166.02 MiB，包括长轨迹及完整 JSON 导出的解析；
这是验证进程的观测，与生产服务的流式下载内存不同，也不是大型数据的资源保证。

## 5. 交付与剩余边界

改动已整合到主目录，软件版本保持 0.8.0。原生网页布局、现有世界、凭证与历史
实验保留；没有新增运行时依赖、默认样本数量或模型权重。

仍需后续验证的内容包括：真实模型试跑、训练或日志校准的语义推荐、真实地理距离、
社区文化与治理演化、完整传播事件和长期行为。当前先解决文档中可以被代码与受控
运行具体检查的缺口。
