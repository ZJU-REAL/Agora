# AI 社媒环境基础链路检查

检查日期：2026-11-23。验收范围按当前需求限定为浏览信息流、看图读帖、图文创作、
点赞/投票、评论/回复，以及实际观察、历史回放和导出。

## 1. 检查结论

**在这个范围内，三平台已经具备可运行的基础社媒评测环境，软件链路通过验收。**
页面、内容规则和主要互动保留了平台差异，可以让接入的模型实际操作并记录结果。
当前线上代码 `309030b` 与本地优化代码 `6841d5c` 都通过了相同的连续操作检查。
本轮扩充的是验收测试与说明，没有新增运行功能、升级版本或部署。

真实模型的网络、认证、JSON 动作输出和行为质量，需要接入具体模型后试跑。检查时
线上模型连接仍为 0；下述模型是受控 HTTPS 协议接口，结果不作为真实 LLM/VLM 能力
结论。

| 需求 | 小红书 | X / Twitter | Reddit | 本轮证据 |

可以从外部生成后走上传接口；平台没有把测试图片当作模型原创内容。

## 3. 连续操作的实际路径

每个受控账号执行 15 次模型决策：

```text
打开图文帖子 → 查看图片/停留 → 点赞或投票 → 评论或回复
→ 返回 → 刷新 → 翻页 → 打开创作页 → 保存图文草稿
→ 发布 → 再次打开发布内容 → 返回 → 刷新 → 结束会话
```

所有动作的对象与素材来自实际账号观察。小红书额外检查图集切换后的图片字节，
三平台检查真实分页、发布后的正文/图片，以及回放对应步骤。回放操作不会再次调用
模型或执行原动作。

### 托管模拟

通过实际 Developer 表单选择模型并启动，每个平台使用两个模型账号：

| 平台 | 决策调用 | 点赞/投票动作 | 评论 | X 回复 | 图文发布 | 失败 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 小红书 | 30 | 2 | 2 | 0 | 2 | 0 |
| X | 30 | 2 | 0 | 2 | 2 | 0 |
| Reddit | 30 | 2 | 2 | 0 | 2 | 0 |

来源世界在启动前预置足够的临时图片卡片，以验收下一页，而不只检查信息池耗尽的
返回值。托管运行结束后，源世界账号、帖子和素材关联计数不变。

### 外部 SDK

三个平台的 `AgoraClient.run()` 分别完成同一段 15 次决策，均无失败；调用方先上传
两张图片，模型选择素材、配文并发布。动作轨迹有 16 条记录（包含初始会话记录），
发布后的完整观察可按对应 `step` 读取。

受控模型走 Chat Completions 兼容 HTTPS 协议，TLS 校验保持开启。这里验收网络协议、
平台工具和视觉输入传递，不把夹具提供的 token 数当作真实用量或费用。

## 4. 当前线上与本地优化分别检查了什么

| 对象 | 验证方法 | 结果 |
| --- | --- | --- |
| 当前线上同版本代码 `309030b` | 从主目录导入实际运行模块，在临时世界和独立端口执行六个连续操作用例 | 三平台托管与 SDK 共 6 项通过 |
| 本地优化分支 `improve/platform-behavior` | 扩充后的 HTTPS 联调模块 | 11 项通过，含旧创作链路、探测格式及六个新连续用例 |
| 真实 IAP 本机代理 | 只读核对页面、平台 API、模型连接、运行状态和历史入口 | 服务正常；未在生产世界创建账号、保存测试模型或启动模拟 |

检查用模型、证书、账号、图片和发布都在临时数据目录。本机代理核对不能替代公司
登录后的外部 HTTPS 客户端验证。当前基础流程并不依赖本地大模型、Docker 或新增
运行时依赖。

## 5. 开始实际评测时的使用要点

1. 优先从 Developer 保存模型连接，填写真实协议地址、模型 ID、API Key 与预算，
   勾选模型确实支持的视觉能力。先测试连接，再启动小规模托管模拟。
2. 给账号提供有区分的内容、图片、Persona 和你希望评测的任务。平台没有默认的
   模型质量答案，成功操作数也不能直接当作创作或互动质量。
3. 需要翻页时，让推荐列表长度大于每页数量。本次采用列表 24、每页 6；当前网页
   默认列表 6、每页 6 时，一批只有一页，可通过刷新取得下一批，不应把正常的
   `end_of_feed` 误判为翻页失败。
4. SDK 的 `trajectory()` 返回轻量动作索引，完整历史画面使用
   `client.observe(step=record["step"])` 获取。它不是返回在每条索引里的大观察对象。
5. 外部 SDK 直接操作自己的源世界会话，不自动加入 Viewer 的托管实验列表。
   需要隔离副本、自动观察、统一回放与导出时采用托管模拟；SDK 可自行读取轨迹与
   模型调用结果。

操作有效率、失败类型、内容、素材、曝光和互动记录已经可以用于分析。文案/配图
质量、互动是否合理、模型是否真正看懂图片，仍应由你选择的评判方式和真实模型试验
确认。
