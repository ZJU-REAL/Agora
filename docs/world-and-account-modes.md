# 世界模式与账号起点设计

本轮沿用 0.8.0，在独立工作树实现并验收，不自动合并、升级版本或部署。

## 已确定的产品规则

世界有两种初始化方式：`background` 保留选定源世界的历史账号、内容、关系；`ai_only`
创建空内容世界，所有参与账号新建并由 agent 控制，不导入历史用户、帖子或互动。
必要的空公共社区和可选素材库属于平台资源，不作为已经发布的内容。

账号起点独立配置：`existing` 接手背景世界的已有账号，保留内容与关系；`new` 创建新
账号，默认没有帖子和关注，也可通过 `focal_starter_posts` 从选定模板复制少量公开主帖。
新建账号有少量预置内容仍可做起号实验，复制内容作为初始条件，不能计作 AI 发布成绩。

纯 AI 世界默认零帖子。显式预置账号内容时，准确显示实际起始帖子数量；完整接手历史
账号在背景世界中进行，避免把外部历史用户和关系偷偷带进纯 AI 世界。

受测账号任务与背景任务分开。背景任务按本轮背景账号顺序对应，未分配的账号可自由
活动。任务、账号映射、初始计数和配置冻结在运行记录里。规则策略仅用于调试，任务
理解与模型能力要由接入的真实模型验证。

## 实现范围

- Developer 增加世界模式、新建/接手、模板及最多预置条数、背景账号来源与背景任务。
- 两模式共用现有平台工具、推荐、调度、Viewer、控制和导出；旧配置默认背景世界与已有账号。
- 初始世界总账号数和本轮活跃账号数分别显示；32 活跃账号和 2400 动作预算继续生效。
- 新建初始化只写入实验副本；初始内容/媒体有来源记录，源世界、凭证、旧运行保持。
- 空源世界也可以从网页启动新建账号模拟；不得悄悄加入默认示例帖子。
- 记录明确标出世界模式、账号起点、初始内容和实际任务；新动作指标从新会话统计。

## 验收

三个平台分别检查背景/纯 AI 世界、全新账号、预置内容、接手账号、任务传递、空源
世界、源数据不变、媒体与账号隔离、重用配置、历史回放、导出、预算与启动失败清理。
界面沿用现有插画品牌与表单，验证桌面/手机的真实启动，不修改三个原生平台页面。

## 如何选模式与账号起点

| 实验目的 | 世界模式 | 受测账号起点 | 初始化内容与关系 |
| --- | --- | --- | --- |
| 在已有内容中测试从零起号 | 背景世界 | 新建，预置 0 条 | 世界历史保留，新号没有帖子或关注关系 |
| 在已有内容中测试有基础的起号 | 背景世界 | 新建，预置少量公开主帖 | 新号复制指定内容，原有点赞、评论、关注不复制 |
| 测试代替运营 | 背景世界 | 接手已有账号 | 使用该账号的资料、内容、关系和素材权限 |
| 观察任务驱动的社区自然形成 | 纯 AI 世界 | 新建，预置 0 条 | 只有参与账号，初始帖子与互动为零 |
| 比较不同起步内容的效果 | 纯 AI 世界 | 新建，显式预置少量内容 | 不导入历史账号，单独记录账号预置内容 |

世界历史和本轮活跃人口分别计数。背景世界里未被选中的账号保留在数据库中，不自动
充当真人或持续产生内容；动态行为由本轮参与账号和明确配置的背景事件产生。小型演示
世界仅有 4 个虚构账号、6 条主帖，选择背景世界不会自动变成大型真实数据集。要测试
复杂舆情，需要先按研究目的导入合适的数据、角色和传播结构。

账号的模板人设与实际身份分开：模板可提供兴趣、语气、简介等资料；新账号仍获得独立
ID、handle 和显示名。Persona 中的示例文本属于模型语境，不自动发布成帖子。

## Developer 使用步骤

1. 选择小红书、X 或 Reddit，再选择世界模式。
2. 选择受测账号起点。接手时选择源账号；新建时填显示名，可选模板与 0–20 条预置上限。
3. 配置参与 agent 总数。总数包含受测账号；背景世界可优先使用已有账号，或全部新建。
   纯 AI 世界中的参与账号全部新建。
4. 分别选择受测模型与背景策略。填写受测任务；背景任务每行对应一个背景账号，空行
   或未分配位置表示自主活动。规则开发策略不理解自然语言任务，任务研究应连接模型 API。
5. 检查启动摘要和总动作预算，启动后在 Viewer 查看初始条件、实际观察和动作。

最多预置条数不是保证条数：模板只有 2 条符合条件的主帖时，填写 5 也只复制 2 条。
选择没有符合条件主帖的模板而要求预置会被拒绝。预置按源主帖 ID 从新到旧选择，保留
原内容、标题、主题、地点、时间和媒体顺序；只接收未删除、未被移除、公开社区中的
公开原创主帖。回复、转发、评论、历史互动不复制到新账号。

公开素材库与已发布内容分别管理。关闭“为新账号提供公共素材库”时，不额外提供创作
素材；预置图文自身所需媒体仍会复制。纯 AI 世界最多沿用 100 个空公共社区结构；没有
公共社区的 Reddit 世界提供空的 `r/general`。公开社区结构不保留历史创建者或版主关系。

配置按平台在当前浏览器保存。复用运行配置时，新号引用原先的源模板，接手账号引用
源账号；不会错误引用上一次实验生成的账号 ID。源账号超过首批 200 个时可搜索。
手机端优先展示模式、账号起点、背景数量、总预算与启动；其他模型/运行细节在配置中。

## 研究配置字段

以下字段传给 `ExperimentManager.start()` 或研究控制台 `POST /api/runs`。
网页请求另带 `platform` 选择世界；AI 账号专用端口不开放这些研究路由。

| 字段 | 类型 / 默认值 | 含义 |
| --- | --- | --- |
| `world_mode` | `background` / `ai_only`，默认 background | 历史背景或纯 AI 初始化 |
| `focal_start` | `existing` / `new` | 背景默认 existing，纯 AI 默认 new |
| `focal_user_id` | 源账号整数 ID | 接手账号；新建的兼容请求可把它当模板 |
| `focal_template_user_id` | 源账号整数 ID，可省略 | 新号的 Persona 和预置内容模板 |
| `focal_starter_posts` | 整数 0–20，默认 0 | 新号最多预置多少公开原创主帖 |
| `new_account_name` | 1–80 字符，默认“受测新号” | 新号显示名 |
| `focal_profile` | Persona 字典，默认空 | 覆盖模板人设中的部分属性，新身份由初始化器生成 |
| `background_start` | `existing` / `new` | 背景默认优先已有，纯 AI 只允许 new |
| `agent_count` | 整数 | 参与总数，包含受测账号；网页上限 32 |
| `user_ids` | 源账号 ID 列表，可省略 | 明确指定已有参与者；新号另计 1 个，最终实际 ID 冻结到记录 |
| `goal` | 0–4000 字符 | 受测账号任务；空字符串表示自主活动 |
| `background_tasks` | 字符串列表，每项最多 4000 字符 | 按背景位置分配，不能多于背景账号数量 |
| `include_starter_assets` | 布尔，默认 true | 为新账号提供可用的公开创作素材 |

新建的空源世界可使用 `agent_count` 与 `focal_start: "new"` 启动，不要求伪造源账号。
初始化过程先完成并冻结初始状态，再创建新运行会话。初始化失败会清理不完整实验目录。
旧的无模式配置默认背景世界；只有 `user_ids` 且不指定受测账号/总数的历史请求仍保持
原来的共享 provider 和任务行为。网页复用这类历史配置时，会明确填回对应背景任务。

例如以下研究控制台配置启动一个零内容世界。`registered-model-id` 需换成自己已保存的
模型连接 ID；任务文本仅为例子，可以改为自己的研究情景。

```json
{
  "platform": "xiaohongshu",
  "world_mode": "ai_only",
  "focal_start": "new",
  "background_start": "new",
  "new_account_name": "摄影起号实验",
  "agent_count": 4,
  "focal_starter_posts": 0,
  "include_starter_assets": true,
  "provider_id": "registered-model-id",
  "background_provider_id": "registered-model-id",
  "goal": "创作摄影主题图文，查看公开反馈并与社区互动。",
  "background_tasks": ["分享一次自己的拍摄体验。", "围绕摄影内容提出具体问题。", ""],
  "ticks": 6,
  "steps_per_tick": 8,
  "seed": 42
}
```

测试带内容的新号：在上述配置增加实际 `focal_template_user_id`，把
`focal_starter_posts` 调为需要的上限。测试接手运营：改用背景世界与 existing，填写实际
`focal_user_id`，去掉新号预置字段。纯 AI 不允许接手账号或注入研究者历史账号的背景事件；
需要热点事件时，把创作任务交给本轮参与账号，或在背景世界配置研究事件。

## 记录与评测口径

每场运行的 `config.initial_state` 固定记录世界模式、账号起点、实际 focal ID、世界总
账号数、活跃账号数、初始帖子/评论/媒体数、受测账号初始帖子/素材数，以及每条预置内容
与源帖子 ID 的映射。`config.agent_goals` 固定记录实际账号与任务对应关系。

Viewer 显示初始模式、账号起点、初始帖子和账号数。行为指标只统计本轮新会话中的成功
动作，预置内容不计作 `created_posts`。完整导出保留初始条件、模型调用、实际动作与
观察；超过 128 项的初始媒体清单按文件流完整导出，避免整库载入内存。

起号评测可以比较第一条发布时间、有效曝光、互动转化、后续内容与社交关系变化。
接手运营可以比较内容延续性、受众互动和任务完成情况。初始历史、模板、人设、任务、
推荐、seed、模型身份和预算应固定，才能比较不同 agent；这些评测指标尚未打包成自动
评分榜单。小样本自然形成社区也不等同于真实规模的人类社会。

## 本轮验证结果

完整回归 **446 passed**，没有失败或跳过。新增 89 项检查中，66 项覆盖初始化与隔离、
20 项覆盖浏览器配置/启动/复用/空源/搜索，3 项通过本地受控 HTTPS 模型验证纯 AI 零内容
到图文发布与独立任务传递。后者每平台 2 个账号、8 次决策、2 条图文发布，0 失败。
验证使用图片字节和 TLS 校验，但响应来自确定性接口夹具，不能作为真实模型能力证据。

检查保留了源世界的数据与素材，实验副本不含源账号 API token；新号不继承关系和旧点赞。
同版本 wheel 和界面复核结果记录在 [验证状态](validation.md)。软件版本仍为 0.8.0；
这轮没有推送、合并、部署或重启生产服务。
