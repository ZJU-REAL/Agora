# 工作台使用流程

Agora 0.7 按“配置 → 启动 → 观察 → 复用”的流程组织框架前端，保留官方插画品牌与三种
社媒的独立原生页面。本轮参考维护者提供的《Agora Web 前端整体优化与产品体验重构》，
优先解决上下文、实际观察和操作效率。

| 页面      | 主要操作                                                                 |
| --------- | ------------------------------------------------------------------------ |
| Developer | 选择平台，直接探索；配置受测/背景账号及模型；检查动作预算；启动独立模拟  |
| Viewer    | 选择实验和账号；跟随最新或回放；定位操作；读取实际画面、理由与结果；导出 |

顶部只提供两种工作模式。Developer 的侧栏只导航配置、实验记录和模型连接；平台探索
放在平台选择旁，不再放在侧栏底部。插画缩小为品牌提示，工作区域用白色表单、蓝紫色
选择状态和分隔线组织。

## 配置与上下文

受测账号来自所选平台的已有账号。背景账号按账号 ID 从其余已有账号中选择，数量不足
时由后端在实验副本内生成。页面明确展示已有与新增背景账号数量；各自的模型或规则
策略独立选择。运行意图可留空，不预置或强制研究任务。

总动作预算为 `账号总数 × 模拟轮数 × 每轮动作上限`，与服务器资源限制一致。未配置
凭据的模型、超预算和无效分页配置有明确提示；开发策略不调用模型 API，页面不把它
包装成真实模型结果。服务器仍保留最终校验，页面检查不替代后端限制。

各平台的未完成配置在当前标签页独立保存，显式“保存配置”写入该平台的浏览器存储。
旧版单份配置仅在平台匹配时恢复。存储不包含模型密钥。API Key 仍只保存在服务器端，
关闭模型窗口会清空未保存的密钥。

“复用配置”读取原实验的账号和推荐参数，保留未在表单中展开的推荐权重；如果原账号
或模型已不可用，要求重新选择。它只填入配置，启动后创建新实验，不修改原记录。

## 观察与回放

Viewer 中的平台画面只读；手动探索是另一个可操作的源世界入口。原生小红书、X 和
Reddit 的 HTML、CSS 与脚本不套用框架设计系统。放大/恢复只改布局，保留同一 iframe。

回放位置按 `实验 ID + 账号 ID` 保存，最近 8 场实验有界保留。切换账号恢复该账号自己
上次查看的步骤；页面明确说明“账号独立时间线”，不将不同账号的第 N 步误当作同时
发生的事件。URL 携带平台、实验、账号和所选历史步骤，刷新后可恢复。

历史选择先读取对应步骤的完整观察，再更新动作详情与原生画面。异步请求有版本检查，
避免慢请求覆盖后来选择的步骤或账号；播放在一次画面读取完成后再安排下一步。
“跟随最新”取消未完成的历史选择；已结束实验显示“历史回放”和“最新步骤”。

当前动作展示实际执行结果、动作后的观察摘要及已记录的公开理由。未记录理由或结果
时明确说明缺失，不生成解释。参数和完整结果按需展开。

账号行为概览与筛选来自该账号完整的轻量动作索引：浏览、创作、互动、关系/社区和
会话/其他。失败筛选只依据记录中的 `success=false`。计数包含操作尝试，不等同于
成功创作数或能力得分。该概览帮助定位行为，不引入任务评测或推断性指标。

## 资源与边界

继续使用静态 HTML/CSS/JS、Python 与 SQLite，没有新增运行时依赖。默认 1 个并发模拟、
32 个活跃账号、2400 次动作，历史完整观察仍最多缓存 4 帧。不扩大预置样本，不加载
本地模型权重，也不为每次模拟启动 Docker。

验证记录和浏览器限制见 [验证状态](validation.md)。本轮没有新增账号级 RBAC、多账号
同步全局时间轴或复杂分析系统；这些不能仅通过界面制造存在感。
