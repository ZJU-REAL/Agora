# 原生沙盒、实验管理与账号协议

0.3 的工作台入口是 `agora serve <world> --bootstrap`，默认地址 `127.0.0.1:8765`。
原生世界位于 `oasis/world.py`，历史目录名不代表使用旧 OASIS runtime。安装与模型配置
见 [README](../README.md)，相关工作的实际设计依据见 [research.md](research.md)。

## 实验生命周期

1. 页面选择源世界中的账号、轮数、每轮动作上限、种子、策略/模型、目标和推荐参数。
2. 创建独立世界目录，备份 SQLite、复制媒体并校验 SHA-256。manifest 记录引擎版本、
   配置、初始数据库/媒体指纹和模型配置指纹。
3. 后台线程拥有该世界的写连接，按 seed/tick 决定账号顺序。HTTP 页面通过只读事务
   查看一致的快照，持续显示进度和每个动作。
4. 动作保存公开观察、参数、简短公开理由、结果与模拟时长；模型调用另记身份、已知
   token、延迟和失败。记忆来自账号自己的公开观察与实际动作/结果。
5. 可在动作边界暂停/继续/停止。默认快速运行，也可设置 `pace_ms` 放慢观察速度；
   它只改变展示速度，不改变模拟时长、seed 或推荐结果。
6. 完成/停止后保留独立数据库、媒体和 manifest；页面可回放、查看图文草稿及素材顺序，
   完整导出包括逐步观察、推荐诊断、世界事件和模型调用。

本地每次模拟不依赖 Docker。最多同时四个实验，各自单写者 SQLite。源世界手动操作
不修改已克隆的运行。进程重启把未完成任务标记为 interrupted，保留记录，不自动重发
模型请求；正式受控评测仍使用既有 Runner 的 checkpoint/resume。

## 账号的产品流程

| 屏幕 | 行为 |
|---|---|
| 发现/关注/搜索 | 刷新、滚动、打开可见帖、不感兴趣、关注或取消关注已知作者 |
| 内容详情 | 完整正文/图片/视频、评论树、阅读停留、赞/收藏、评论和返回 |
| 个人主页 | 自己或已知作者的公开信息、关注/粉丝计数、按时间排列的可见帖子 |
| 通知 | 自己收到的点赞/评论/回复，不向其他账号显示私密通知 |
| 创作工作台 | 查看账号素材库、选择素材/顺序、保存图文草稿、发布并查看反馈 |

`view_profile`、`open_notifications`、`open_studio`、`save_draft` 和 `publish_draft` 接入
与浏览相同的会话轨迹。`create_post` 可直接发布文字、图片、多图或视频，素材必须用
账号库中的 `asset_id`，模型不能提供主机路径。页面目前提供图文素材选择，视频制作的
完整交互仍需扩展。底层已有 X quote/repost 和 Reddit 原生能力，尚未全覆盖会话工具。

卡片只给摘要和封面，打开后才能读完整内容和评论。只有进入实际页面的卡片计曝光，
同一推荐请求中的同帖不重复计数；候选集合不等于曝光，更不等于阅读。模型看不到
隐藏推荐分数。VLM 的图片/视频帧只存在于请求中，base64 不写入数据库或轨迹。

## 推荐 v2

默认 `agora-hybrid-v2`：新内容、关注、话题兴趣、热门、探索窗口与协同召回。协同召回
从共同点赞寻找至多 20 个邻居，再在可见内容中召回邻居的正反馈帖子。每路最多
`channel_limit` 条；协同特征只查询有界候选，不加载邻居的完整历史。

排序组合兴趣先验、衰减反馈、关注、平滑质量、时效、曝光疲劳与协同亲和；随后对重复
作者/话题作软惩罚，约每五条插入探索位。Persona 权重与反馈限制在 [-3,3]。打开、赞、
收藏、评论与有限停留影响兴趣；取消互动和“不感兴趣”有反向作用。评论权重表示关注
程度，不能解释为正向情绪。自己的主页浏览不进入推荐点击率计算。

同会话优先避免已看帖子，召回池耗尽时允许带疲劳的重复并标记 `repeat_fallback`。关注流
仅显示关注作者；搜索全文/话题作字面量匹配。当前没有语义搜索或中文分词。v1 保留用于
既有配置，其排序不启用协同召回。受控 Arena 不静默切换到新推荐模式。

这仍是可检查的规则/协同代理，没有训练 embedding、CTR 网络或厂商实时模型。SQL
热门/探索召回可能扫描合格内容，大世界需要索引和缓存进一步优化。

## 存储和复现

`WorldStore` 管理迁移与嵌套 savepoint。复合会话动作中的内部 commit 被外层事务接管；
若结果持久化失败，数据库、会话内存与新导入媒体一并回滚，不删除已复用的素材。
新媒体按内容 SHA-256 寻址，同一素材复用相同 ID，减少重复存储并稳定语义轨迹。

`agora_session_event` 保存实际公开屏幕；`agora_request` 保存版本/配置/召回/重排诊断；
`agora_exposure` 保存页面曝光；`agent_memory` 保存有界账号经验；`agent_model_call`
保存调用证据。历史观察不随当前计数变化而改写。模型历史读取只取最近八步，避免每次
动作重复加载全部历史；实验账号观察页面增量拉取新增步骤。

同一初始世界、配置、seed 与开发策略可复现语义轨迹。模型响应与网络不保证确定性，
回放读取保存结果而不是重新调用模型。不同推荐/曝光/预算条件不能混作同一个实验。

## 本地 API

| 路由 | 用途 |
|---|---|
| GET `/api/world` | 源世界的账号和会话 |
| POST `/api/runs` | 创建独立实验，配置含 user_ids/ticks/steps_per_tick/seed/provider_id |
| GET `/api/runs` | 实验列表和可用 provider 元信息，绝不返回密钥 |
| GET `/api/runs/<id>` | 进度、动作、指标、关系图和模型调用 |
| GET `/api/runs/<id>/export` | 完整公开观察与研究者诊断导出 |
| POST `/api/runs/<id>/control` | `{"command":"pause"}` / resume / stop |
| GET `/api/run-world?run=<id>` | 运行世界只读账号列表 |
| GET `/api/run-session?run=<id>&id=<session>` | 只读观察/回放，支持 after 增量步骤 |
| POST `/api/session`、`/api/action` | 手动操作源世界 |

控制台属于拥有整个世界的研究者，可看诊断和素材；模型使用 `SocialSession.observe/act`
受限接口，不使用这些研究者 HTTP 路由。当前绑定 loopback，多人鉴权和分布式服务未实现。
