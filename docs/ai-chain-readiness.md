## 可以怎样使用

推荐从 [Developer](https://lidingm.iap.platform.shaipower.com/agora/developer) 的“模型连接”
保存模型接口，然后选择受测账号模型和背景策略、启动模拟。系统读取账号实际可见的
数据与图片，通过平台工具执行模型返回的 JSON 动作，Viewer 显示该步骤的原生平台
画面、执行结果及已记录的公开理由。

首次真实试跑建议：2 个账号、1 轮、每轮至多 4 个动作；受测账号使用模型，背景账号
使用开发策略；每账号请求预算 12、输出 token 上限 512。受测账号至多产生 4 次决策
调用，连接探测额外调用一次；提前结束或长时间停留可能减少实际动作数。视觉开关应
与模型真实能力一致。不在网页服务中加载模型权重。

保存模型需要接口协议、HTTPS 服务地址、模型 ID、API Key 和预算。支持 Chat Completions
兼容接口、Gemini generateContent 和 Runway Gemini 网关。连接探测检查模型身份与
`{"ok":true}` 的 JSON 响应；它验证接口契约，不代表模型已经具备可靠运营能力。
0.7.1 修复了“普通文本响应也显示连接成功”的问题，错误响应不回传密钥或上游原文。

当前默认部署的模型配置位于
`data/worlds/agora-iap-small/.private/providers.json`，权限为 0600。API Key 不需要写入
聊天、仓库或实验导出。

## 尚未闭合的边界

- 真实模型的网络、认证、输出格式、看图能力及行为质量需要接入具体服务后试跑。
- 外部 SDK 直接操作的是源世界会话，目前不会自动成为 Viewer 下拉框中的托管实验；
  SDK 可以读取自己的轨迹。需要自动观察、隔离副本和导出时，先采用 Developer 托管模型。
- 外部模型调用记录由 SDK 返回给调用方；平台 API 记录动作与公开理由，不掌握外部
  推理服务的真实调用日志。托管实验的调用记录在服务器端保存。
- 真实推荐/行为校准、长期运营和多 seed 能力研究没有被这次接口验收替代。
